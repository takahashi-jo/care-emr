# CareEMR 要件とロードマップ

## ゴール

介護老人保健施設（老健）の**常勤医師向け**電子カルテ。医師の回診・健康管理・投薬・診療録を最速で回せることを軸にする。将来的に他施設への導入（事業化）を目指す。医療データを扱うため真正性・セキュリティを重視する。

## 機能比較（老健カルテ(ND)等 × CareEMR）

| 機能 | 一般的な老健EMR | CareEMR | 判定 |
| --- | --- | --- | --- |
| 入所者管理 | ○ | ○ | OK |
| 経過記録（診療録） | ○（POMR） | ○ 自由文＋監査/訂正履歴 | 概ねOK |
| 処方/投薬 | ○ | ○ 構造化＋医薬品マスター(約1.8万剤) | 優位 |
| 全入所者一覧/回診ビュー | ○（一覧が基本） | ○ 一覧デフォルト＋継続薬表示＋絞り込み | OK |
| バイタル記録（体温/血圧/脈/SpO₂/体重/血糖） | ○（機器連携） | ○ 時系列＋異常値強調・監査/論理削除 | OK |
| プロブレムリスト（POMR） | ○ | ○ 問題一覧＋現行/消失（診療録のSOAP化は次） | 概ねOK |
| 検査結果 | ○ | ○ 項目別の時系列＋推移グラフ・基準値外強調 | OK |
| 主病名・既往の構造化（病名マスター/ICD-10） | ○ | ○ 病名マスター(diseaseMaster)＋ICD-10、問題名で連携 | OK |
| 感染症・予防接種歴（インフル/COVID/肺炎球菌等） | ○ | ✕ | 老健で有用 |
| 看取り・ACP（DNAR/急変時方針/家族の意向） | ○ | ✕ | 高齢者施設で重要 |
| 在宅復帰支援の記録（入退所判定・3ヶ月更新） | ○ | ✕ | 老健特有・要検討 |
| 多職種の記録参照（看護/リハ） | ○ | ✕（医師専用） | スコープ判断 |
| LIFE連携（CSV出力） | ○ | ✕ | 補助金/加算で重要 |

医師業務は回診（週1回＝月4回）が中心。全入所者をフロア/部屋順で一覧して回るのが自然なため、「検索必須」ではなく「一覧をデフォルト」にする。

## ロードマップ

### 完了
- ローカル開発環境（Firebase Emulator、Node は mise で node@22 固定、WSL越しアクセス対応）
- 投薬の構造化（`residents/{id}/medications` サブコレクション、医薬品マスター `drugMaster` 約1.8万剤、YJ/HOTコード保持）
- 旧 `medications:string[]` の構造化移行と旧UI撤去
- 診療録の追記型＋監査（`createdBy`/`updatedBy`、訂正履歴 `revisions`、論理削除、ルールで物理削除禁止・作成メタデータ不変）
- UI共通化（一部）：`common/ModalHeader`・`ModalShell`・`Button`・`FormField`・`FormControls`、登録/編集フォームを共通部品化
- **回診ビュー**：全入所者一覧をデフォルト表示（部屋/氏名/要介護度で並べ替え、退所者トグル、継続薬の一覧表示、氏名/部屋/要介護度/継続薬での絞り込み、登録・編集・投薬変更の即時反映）
- **UI仕上げ**：配色トークンを `tailwind.config.js` に一元化（slate基調＋落ち着いた青）、アイコンを `@heroicons/react` に統一、削除ダイアログ/通知/空状態を共通部品化
- 投薬 collectionGroup 検索のルール（`match /{path=**}/medications/{id}`）
- **バイタル記録**：`residents/{id}/vitals` に体温/血圧/脈拍/SpO₂/体重/血糖を時系列で記録。新規/編集/論理削除・監査付き、異常値を赤で強調。回診一覧の操作列に導線。検査結果も同じ器で拡張できる設計。
- **バイタル推移グラフ**：Recharts で項目別スモールマルチプル（閾値の基準線＋異常値の赤マーク）。lazy 読み込みでコード分割し初期バンドルを軽く保つ。
- **プロブレムリスト（POMR）**：`residents/{id}/problems`。ICD-10 病名マスター（`diseaseMaster`、MEDIS 標準病名マスター）＋オートコンプリート、現行/消失、監査・論理削除。回診一覧に導線。
- **多言語対応（ja/en）**：react-i18next で文言をキー管理し、ヘッダーで言語切替。UIは全てキー化（臨床データの中身は日本語のまま）。
- **検査結果**：`residents/{id}/labResults`。1採取＝複数項目、項目別の時系列一覧＋推移グラフ（基準線・基準値外を赤）。検査項目マスター（参考基準値つき）を `constants/labReference.ts` に定義。

### 次（要件ギャップを埋める）
- **診療録のPOMR化**（診療録に問題への紐付けと SOAP 構造を任意で追加。既存の自由文は維持。既存機能に触れるため着手前に方針を確認する）
- **UI整理**：回診一覧の操作アイコンが8個で密。患者カルテ（タブ集約）またはオーバーフローメニューへの集約を検討。
- **老健特有の軽量追加**（ACP/看取り方針、予防接種歴）— アレルギーと同様に入所者へ構造化フィールドで付与

### 事業化
- **LIFE連携**（標準仕様でCSV出力）
- **マルチテナント化**（`facilityId` でデータ分離。多施設展開の前提）

### 横断（随時）
- **リポジション**：README は老健医師向けに刷新済み。CLAUDE.md も同様に統一する。
- **効率化**：診療録テンプレート/定型文、常用薬のセット処方・処方履歴からの再利用、回診の当日ワークリスト化（前回申し送り・バイタル異常フラグ）
- **真正性の見読性**：操作監査ログの一覧UI、データのエクスポート/バックアップ
- **依存更新**：既存の開発依存に脆弱性が残る。lockfile を再生成のうえ、破壊的変更を避けて計画的に更新する。

### スコープ判断（要相談）
- 多職種連携（看護/リハ記録の参照）、介護記録（食事/水分/排泄）の閲覧 — 「医師専用ツール」を超えるかどうか。

## 命名・ブランディング（製品化時）
- 現状の名称「介護施設電子カルテシステム」は範囲が広い。実体は**老健の常勤医師向け（回診・投薬・診療録が核）**なので、それが伝わる名前に寄せる。
- **技術メモ**：Firebase の**プロジェクトIDは後から改名不可**。ブランド名に合わせるなら (a) App Hosting に**独自ドメインを接続**してユーザーからプロジェクトIDを隠す（推奨・低コスト）か、(b) 新プロジェクトを作成し Firestore/Auth をエクスポート＆移行。表示名（display name）は随時変更可。
- 命名候補・最終決定は別途（決まり次第ここに追記）。

## デザイン方針
- **配色**：ニュートラル（slate/gray）基調＋彩度を抑えた青アクセント。ヘッダーはフラット寄り、影・境界は控えめ。バッジ色（緑/赤/紫）も彩度を下げて統一。
- **アイコン**：`@heroicons/react` のコンポーネントのみ（自作SVG禁止）。
- **UI部品**：`src/components/common/` の共通部品（ModalHeader/ModalShell/Button/FormField/FormControls）を使う。
